Feature-level spatial alignment components

Install PyTorch, NumPy, SciPy, h5py and scikit-learn in a Python environment. Dependency names are listed in code/requirements.txt.

The input reader expects an NPZ archive with arrays named features (region by feature), omics (region by gene or marker), coordinates (region by 2), slide and patient (one string per region). Coordinates must share units within each slide. A slide must contain at least seven regions when using six neighbours. Input features must already be extracted and paired with omics from the same spatial region. The format is an engineering interface, not an official cohort format.

The code operates on precomputed features. It does not include a CONCH vision encoder, image tiling, omics deconvolution, Leiden clustering, a complete training run, clinical assessment or reported study results. The multi-scale implementation uses four feature blocks to include both neighbour mean and variance; this is an explicit engineering interpretation of a dimensional inconsistency in the manuscript. Consult claim_to_code.json and verification_report.json for coverage and limitations.

CODEX imaging of HCC is distributed by The Cancer Imaging Archive under CC BY 4.0, with required dataset attribution: Ruf and colleagues, Highly multiplexed spatially resolved immune cell atlas of hepatocellular carcinoma (CODEX imaging of HCC), version 1, 2023, DOI 10.7937/BH0R-Y074. Each dataset and external model remains subject to its own terms. CONCH is maintained by the Mahmood laboratory; the official implementation is https://github.com/mahmoodlab/CONCH and its model weights require access approval. HEST's current dataset card states CC BY-NC-SA 4.0 and requires acceptance of its conditions; this differs from the manuscript's stated CC BY-NC 4.0. Dataset identifiers and source links are recorded in dataset_urls.txt.

HEST and TCGA-LIHC inputs

The HEST reader requires h5py and SciPy in addition to the dependencies above. load_hest_pairs accepts a HEST AnnData HDF5 expression file, its HDF5 patch file, and an explicit ordered list of unique gene names. Gene selection must use the training data only. The reader joins by barcode, preserves the expression file's spatial coordinates, and returns the raw X values; it does not perform normalisation, niche aggregation, or highly-variable-gene selection. Both sparse CSR/CSC and dense X encodings are supported. HestPatchDataset reads each matched image from the patch file.

The default patch size is 256, as stated in the manuscript. HEST benchmark's supplied HCC patches are 224 pixels; setting expected_patch_size to 224 permits their use for format checks and experiments with an explicit size change, not as an exact implementation of the stated image protocol. To adhere to the manuscript, extract matching 256-pixel images at 20x from the aligned whole-slide images and preserve their barcodes. The reader accepts a separately extracted feature archive with barcodes and features through HestPairs.region_features. Those features must actually come from the intended encoder; the reader does not create CONCH embeddings.

read_hest_split accepts official benchmark split CSVs with sample_id, patches_path and expr_path columns. Patient-level separation cannot be established from these files alone. assert_hest_patient_disjoint requires a verified sample-to-patient mapping and rejects missing or overlapping patients. The provided files do not establish the manuscript's exact training partition.

read_gdc_cases reads GDC cases API JSON with expanded diagnoses and demographic data. It extracts stage, vital status, and available follow-up durations while preserving missing values. TCGA-LIHC bulk expression and clinical metadata are not paired spatial omics, and the reader does not infer immunotherapy response from survival or tumour stage. CODEX raw-channel processing and registration, the controlled EGA dataset, and official model weights remain outside the validated data path. The downloaded files used for validation are not distributed with this project.
